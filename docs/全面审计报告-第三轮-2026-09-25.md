## 一、项目整体状态

**结论：项目具备继续开发、团队协作与业务验证的基础条件；本轮修复后 gate 全绿，无 P0 遗留。**

- **当前状态**：地基期收尾（F0–F13、F15、F17 ✅；F14 🟡 剩 4 个基础组件；F16 剩 L4 真平台验收）。
  业务路由（I1 订单域起）尚未开工；已落地的是可插拔支付底座（Stripe Checkout / Mock）、统一回调入口、
  幂等 / 事务 / 事件总线 / 调度器骨架、17 张表（migrations 001–009）、脱敏与日志体系、契约随库与门禁体系。
- **成熟度**：工程纪律成熟度高于功能成熟度。变异测试 65 个突变体 **50 被杀**，说明"缺陷注入验证"纪律
  基本属实；存活的 15 个集中在 4 类真实缺口（本轮全部补杀或登记）。
- **主要优点**：① 门禁体系自守（gate 自身、覆盖率阈值、契约随库、结构不变量都有"会红的检查"）；
  ② 资金链路（幂等栅栏、webhook 四态、验签、金额取整）在变异测试下全部被精准命中；③ 决策可追溯
  （AJ 台账 + jp 决策日志 D-xx 双向引用）。
- **主要问题（本轮修前）**：① 生产残留 mock 密钥即注册 mock 回调通道（S1，高）；② 日元在 UI 层渲染成 `¥`
  直接违反 D-36（A1，P1）；③ `country_profiles` 种子文案承诺"含运费"违反 D-32（A2，P1）；④ async 订阅者
  异常逃出事件总线 → 进程 fatal 退出（P2-1）；⑤ 事务幂等把 handler 内 55P03 当占位冲突静默重跑（P2-2）；
  ⑥ Stripe 建会话缺 D-49 参数（3DS / 账单地址 / expires_at）；⑦ 三处门禁盲区（契约枚举子串匹配假绿、
  cov 可去 `--coverage`、render.yaml 键名不受检）。
- **最大风险**：**业务路由零实现**的同时，已实现片段与知识库口径之间存在漂移（本轮抓到 A1/A2/A3 三处
  用户可见的口径反转）——I1 铺开前若不建立"每个单元交付时对照 D-xx"的动作，漂移会按页面数放大。
- **当前最重要的技术债务**：① 落账不绑定通道（`markOrderPaid` 不核对 `payments.provider`，I1 状态机接线前必做）；
  ② `idempotency_keys` 无清理路径（"24h 后同键可重执行"当前是假的）；③ jp 技术文档 §3/§8 与 migrations、
  `.env.example` 的漂移累积（4 张表、16 个键）；④ admin-web 钉在 vite 5（EOL 线）且与 vitest 的 vite 8 并存。
