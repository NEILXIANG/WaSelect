## 2. 扫描规则与范围

- 横向：同类写法在别的文件 / 页面 / 接口 / 任务；纵向：写法不同但根因相同（别的业务流、数据链路、重复规则）；关联：状态 / 异常 / 并发 / 权限 / 测试盲区。
- 范围：`server/src`（adapters / app / domain / ports）、`packages/shared`、`admin-web/src`、`miniprogram`、`contracts/api-contract.yaml`、`migrations`、测试、CI。
- 用三个只读扫描（M1 状态判定点 32 处；M5 三参 / 消费方 / 契约三方比对；M6 多行锁事务 24 个 + 管理端写路由 20 条）产出候选，再由我逐条读码核实。
- 结论先说：**M6 锁序全仓无反转**（24 个多行锁事务锁序一致：users → orders → payments → products；block-user 与 expire-orders 对 orders 的加锁顺序不同，靠 `skip locked` 单向等待，注释已说明）；
  **M5 的"参数位置"类只剩 1 处**（C-3）；M1 里最硬的一条是 C-1。
