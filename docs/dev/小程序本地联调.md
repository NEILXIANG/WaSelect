# 小程序本地联调（模拟器 ↔ 本机服务端）

> 状态：已实测打通（2026-10-01）｜适用：本机开发
> 前置：PostgreSQL 已在跑；`.env` 已由 `.env.example` 复制并填好
>  sibling：`dev/stripe-listen-cloudflared.md`（Stripe 回调转发 / 公网隧道，联调支付时看那篇）

**这篇解决一件事**：让 `miniprogram/` 这个**生产小程序**在开发者工具模拟器里跑起来，
并且真的打到本机 `localhost:3000` 的服务端，而不是只显示一堆写死的假数据。

---

## 1. 一次跑通（四条命令）

```bash
# ① 数据库在跑吗
pg_isready                       # 期望：/var/run/postgresql:5432 - accepting connections

# ② 起服务端（建库 → 迁移 → 灌数据 → 监听 3000）
cd /Users/neilxiang/Documents/me/jp_project
npm run dev

# ③ 打开小程序项目（另开一个终端）
/Applications/wechatwebdevtools.app/Contents/MacOS/cli \
  open --project /Users/neilxiang/Documents/me/jp_project/miniprogram
```

`npm run dev` 跑的是 `scripts/dev-up.ts`，一次性做完：读 `.env` → 建库 → 迁移到最新 →
灌假数据（**库非空则跳过**）→ `bootstrap()` 起服务。终端出现
`listening on http://0.0.0.0:3000` 即就绪。

`cli open` 成功后 IDE 会**自动编译并运行模拟器**，不需要你再点「编译」。
模拟器首页出现商品列表 = 打通。

### 1.1 先把 IDE 的服务端口打开（只做一次）

`cli` 命令报 `IDE service port disabled` 时：
微信开发者工具 → 顶部菜单 **微信开发者工具 → 设置…**（`⌘ ,`）→ **安全设置** → **服务端口** → 打开。
端口号每次启动都变，不用记（CLI 自己找）。一般不需重启，仍报 disabled 就重启工具。

⚠️ 开了之后**本机任意程序都能调开发者工具**（能开项目、能上传代码）⇒ 只在自己机器开，用完可关。

## 2. 前置配置（三处，全是 git-ignored，不入库）

### 2.1 `.env`：`WECHAT_DEV_LOGIN`

```bash
WECHAT_DEV_LOGIN=dev
```

- **为什么必须配**：`.env` 里 `APP_ID` / `APP_SECRET` 当前是**空的**（境外主体注册未完成）。
  按 `server/src/app/mount.ts`，两者都空且 `NODE_ENV` 是 development/test 时，装配层才挂
  dev 登录替身；否则 `wechatAuth = null`，小程序一登录就 500
  （日志 `wechat_login_not_configured`）。
- **规则**（`server/src/adapters/wechat/dev-auth.ts`）：`openid = ${WECHAT_DEV_LOGIN}${code}`，
  即 `dev` + 模拟器给的 code。**不校验 code**，所以等价于无密码登录。
- ⚠️ 生产与 **staging** 配它会被 `loadConfig` 拒启（`config.ts` 规则 1c）。

### 2.2 `miniprogram/project.private.config.json`

```json
{
  "appid": "<你的测试号 AppID>",
  "setting": { "urlCheck": false }
}
```

- 文件名带 `private` == **个人本机配置**，已被 `.gitignore` 排除，不会误提交。
- 公共的 `project.config.json` 里 `appid` 是 `touristappid`。
  ⚠️ **`touristappid` 不能用于 preview**（会报 `不存在此 AppID`），但模拟器运行不受影响。
- `urlCheck: false` 是「不校验合法域名」开关——少了它，`http://localhost` 的请求会被 IDE 拦掉。

### 2.3 接口地址：不用改

`miniprogram/config.js` 的 `API_BASES.develop` 已经是 `http://localhost:3000`。
小程序按宿主的 `envVersion` 选地址，开发者工具里 `envVersion === 'develop'`，自动就打到本地。

⚠️ `API_BASES.trial` / `.release` 目前是**空串**（域名待定），`resolveApiBase` 遇到空串直接抛——
这是刻意的：让"正式版没配域名"在启动时响亮失败，而不是静默打到错的地址。
**提审前必须填满这两项**，否则审核员打开正式版就是白屏。

## 3. ⚠️ `cli preview` 不是「在模拟器里跑」的入口（最大的坑）

这一条害我排查了很久，先说结论：

| 命令 | 干什么 | 会不会上传代码包 |
|---|---|---|
| `cli open --project <path>` | **在 IDE 里打开项目**并自动编译运行模拟器 | 否 ← **联调用这个** |
| `cli preview --project <path>` | 生成**真机扫码二维码** | **是**（上传给微信服务器） |

`preview` 因为要上传，必须过 AppID 校验。所以它对**从未在 GUI 里导入过**的项目会报：

```
✖ Preview
[error] { code: 10, message: 'Error: 不存在此 AppID 请检查后重新输入 (code 10)' }
```

**⚠️ 这个报错的表象是"AppID 不对"，真因不是。** 实测对照：两个项目用**同一个** AppID、
同一个 CLI、同一个登录态，`Fetching AppID () permissions` 这行输出都一模一样，
结果一个 ✔（942.6 KB）、一个 ✖ code 10。差别只有一个：
成功的那个是用户在 GUI 里手动导入过的（IDE 内有项目实例），失败的从未导入过。
CLI 对未导入项目走"新建 + 上传"路径，测试号权限列表为空 ⇒ 落到"不存在此 AppID"。

⇒ **别为联调去折腾 `preview`，改用 `cli open`。**
（CLI 也没有"编译并运行模拟器"的独立子命令，`open` 已是最近的一个。）

## 4. 怎么确认是「真联动」而不是「看起来起来了」

界面能显示 ≠ 数据是真的。用下面三条独立证据确认，任何一条不满足都说明没连上。

### 4.1 服务端日志里出现 IDE 发起的请求

把 `npm run dev` 的输出留下来：

```bash
npm run dev 2>&1 | tee /tmp/waselect-server.log
```

另开终端过滤（⚠️ 本机 grep 是 toybox，**不支持** BRE 的 `\|`，用 `-F` 固定字符串）：

```bash
grep -F '"event":"http_request"' /tmp/waselect-server.log | tail -20
```

判据是 `user_agent` 里含 **`wechatdevtools`** —— 那是开发者工具模拟器发的；
我手工 `curl` 打的话 UA 是 `curl/...`，一眼可分。
另外小程序端生成的 `trace_id` 是 **`mp-` 前缀**，也和手工请求的 UUID 不同。

打通时你至少会看到两条：

| 请求 | 说明 |
|---|---|
| `POST /api/v1/auth/wechat/login` → 200 | `app.js` 的 `onLaunch` 无 token 时自动登录 |
| `GET /api/v1/products` → 200 | 首页 `onLoad` 拉商品 |

### 4.2 数据库里真的落了用户

```bash
psql "postgresql://neilxiang@localhost:5432/japan_shop" \
  -c "select id, openid, created_at from users order by created_at desc limit 5;"
```

期望看到 `openid = dev<一长串>`（`dev` 前缀 + 模拟器的 code），
`created_at` 与你点开项目的时间对得上。**这是最硬的一条证据**——
它证明登录链路走的是真实 HTTP + 真实落库，不是前端 mock。

### 4.3 界面上看到的是库里那几件商品

```bash
curl -s "http://127.0.0.1:3000/api/v1/products?limit=50" | python3 -m json.tool
```

当前种子数据只有 **4 件**（不够就 `npm run db:seed` 补）：

| 商品 | 分类 | 日元价 |
|---|---|---|
| 无印良品 化妆水·敏感肌用 200mL | beauty | 1290 |
| 膳魔师 保温杯 500mL | daily | 4500 |
| 日本制 三德刀 165mm（VG10 钢） | kitchen | 12800 |
| SK-II 护肤精华露 230mL | beauty | 25300 |

⚠️ **别点「清缓存」**：清了会重新 `wx.login`，模拟器给的 code 一变，
`openid` 就变成另一个人（`dev` + 新 code）⇒ **新用户**，表现为购物车 / 订单 / 地址全空。
不清缓存就没事——token 存在 storage 里会复用，一直是同一个用户。

## 5. 常见问题

| 现象 | 先查 |
|---|---|
| `IDE service port disabled` | IDE 设置 → 安全设置 → 服务端口没开（§1.1） |
| `cli preview` 报 `不存在此 AppID (code 10)` | 项目没在 GUI 导入过；联调改用 `cli open`（§3） |
| 模拟器请求全失败 / 首页空白 | 服务起了吗（`curl /readyz`）；private 配置的 `urlCheck:false` 在吗（§2.2） |
| 登录 500、日志 `wechat_login_not_configured` | `.env` 缺 `WECHAT_DEV_LOGIN`，且 `APP_ID`/`APP_SECRET` 为空（§2.1） |
| 界面商品跟库里对不上 | 是不是连到了别的服务；`config.js` 的 `API_BASES.develop` 应为 `http://localhost:3000` |
| 清缓存后购物车/订单空了 | dev openid = 前缀+code，code 变了就是新用户（§4.3），**别清缓存** |
| `npm run dev` 报连不上库 | `pg_isready`；PostgreSQL 没起就 `brew services start postgresql@16` |

## 6. 安全口径（与 dev 登录相关）

- `WECHAT_DEV_LOGIN` 开启时，`POST /api/v1/auth/wechat/login` **等价于无密码登录任意身份**
  （知道 code 字符串就能登进对应账号）。它唯一合法的生存环境是本机 / CI。
- 开 `cloudflared` 公网隧道时，**先清空 `.env` 里的 `WECHAT_DEV_LOGIN`**
  （同口径的另一项：`MOCK_CALLBACK_SECRET` 别留空）。见 `dev/stripe-listen-cloudflared.md` §2。
- 生产 / staging 配它会被 `loadConfig` 拒启；装配层 `mount.ts` 再拦一次（双保险）。

## 7. AppID 下来之后会变什么

按 `server/src/app/mount.ts` 的优先级：**真 AppID 优先，dev 替身让位**。

```ts
const wechatAuth =
  config.APP_ID !== undefined && config.APP_SECRET !== undefined
    ? createWechatAuth({ ... })      // 真实：code → 微信 code2session
    : config.WECHAT_DEV_LOGIN !== undefined && (dev || test)
      ? createDevWechatAuth(prefix)  // dev 替身
      : null;
```

⇒ `.env` 一旦填上真实 `APP_ID` / `APP_SECRET`，本机联调就不再走 dev 替身，
而要拿真实 code 去微信换 openid。届时联调前要重新确认：
① 模拟器里的 `wx.login` 还能不能拿到可用的 code；② 用户表里的 `dev*` 前缀用户与真实 openid
不会互撞（前缀设计就是为这个，见 `adapters/wechat/dev-auth.ts` 文件头）。
