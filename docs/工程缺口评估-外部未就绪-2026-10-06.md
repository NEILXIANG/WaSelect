# 工程缺口评估（外部未就绪）

> 状态：2026-10-06 初版。前提：公司未注册、没有支付账号（Stripe 正式 / 微信支付）、没有小程序 AppID、没有域名。
> 方法：不沿用之前的分析结论，直接读代码，并在本机用真实 HTTP 把"买家下单 → 付款 → 管理端发货 → 退款"完整走一遍（全部用替身：开发登录、模拟支付通道、只记日志的邮件、本地图片存储）。
> 同轮做了全量缺陷扫描（服务端钱与订单、服务端管理与基础设施、小程序、管理端与脚本四块），修复记录见 `docs/自主决策记录.md` AJ-373。

## 一、本地全流程演练结果

修复后，在没有任何外部账号的情况下，本机可以完整模拟：

| 步骤 | 结果 |
|---|---|
| 微信登录（开发替身）、首页、商品列表与详情、条款、客服 | 通过 |
| 新增地址（州码白名单生效，`XX` 被拒） | 通过 |
| 报价、建单 | 通过（前提：汇率在有效期内，见下方第 2 条） |
| 模拟支付 → 订单已付款 | 通过（本轮新增本地模拟付款开关后，小程序里点支付即可完成） |
| 管理端待采购列表、报关清单导出、发货、查件链接、全额退款、审计记录 | 通过 |

演练中实测发现并已修复的问题：

1. **报关清单里的电话被加了单引号**（`'+14155550120`）：防公式注入误伤了国际电话号码。
2. **本地汇率过 72 小时整店停售**：开发库的汇率是灌数那天录的，过期后报价全部失败；全新克隆则根本没有汇率。现在 `npm run dev` 每次启动会补一条开发汇率。
3. **小程序里走不到"已付款"**：非审核模式下模拟通道要外部签名回调。新增本地开关 `MOCK_AUTO_CONFIRM`（只允许本地开发 / 测试，预发布和生产配了会拒绝启动）。
4. **全新克隆后小程序登录不可用**：`npm run dev` 生成 `.env` 时现在会填好开发登录替身。

## 二、工程上还没做完的事

### A. 现在就能做、上线必需

| # | 事项 | 说明 | 规模 |
|---|---|---|---|
| A1 | 预发布环境 | `render.yaml` 只定义了生产。Render 自带 `*.onrender.com` 的 https 地址，不需要自己的域名就能先部署一套用于联调 | 中 |
| A2 | 部署等 CI 通过 | 目前推到 main 后平台可能在 CI 失败前就部署；要配成"CI 通过才部署" | 小 |
| A3 | 备份与恢复演练 | 只有平台自带备份；至少做一次恢复演练，并加定期逻辑导出 | 小–中 |
| A4 | 买家注销账号 / 删除个人数据 | 没有接口，隐私政策草案也没写申请途径。日本个人信息保护法要求能处理，微信审核通常也要求有注销入口 | 中（涉及数据与脱敏，按严格档做） |
| A5 | 汇率自动更新或过期前提醒 | 汇率完全靠管理员手动录入，超过 72 小时没人录，整店停止报价（这是有意的保护），但停售前没有任何提醒 | 中 |
| A6 | 外部可用性监控 | 有健康检查和每日心跳，但没有外部探活，出问题最晚约 24 小时才发现 | 小 |
| A7 | 管理员账号停用 | 目前只能直接改库；单人运营可后置 | 小 |

## 三、建议顺序

A1、A2（先有一个能联调的预发布环境）→ B1（Stripe 测试模式真实联调）→ A4（注销与数据删除）→ B3（订阅消息）→ A3、A5、A6。

## 四、本机复现方法

```bash
npm run dev
```

首次会自动生成 `.env`（含开发登录替身与本地模拟付款开关）、建库、迁移、灌数据、补开发汇率并启动服务。已有 `.env` 的本机需要手动加一行 `MOCK_AUTO_CONFIRM=on` 才能在小程序里直接完成模拟付款。
