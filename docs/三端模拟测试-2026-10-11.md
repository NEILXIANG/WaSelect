## 4. 测过、没问题的（不改）
- XSS：商品标题和售后描述里的 `<script>` 在后台、小程序都按文字显示，不会执行。
- 搜“%”得 0 条：通配符被正确转义。
- 草稿 / 下架商品有明确的“已下架”页；售罄商品的按钮置灰。
- 已签收的单不给“确认收货”：这是有意设计，承运商已确认送达，7 天后自动完成。
- 表情在截图里显示为空白：库里存的是对的，开发者工具缺字体，真机正常。

## 6. 剩余风险（已知、未修）
- 中国手机号“138 0013 8000”会被当成美国号 +1 (380) 013-8000 接受：11 位、1 开头，格式上无法区分。现在电话分段显示，买家更容易自己发现。
- 订单详情的“支付”一栏显示通道代号（mock / stripe / wechat），运营认得，但不是中文。
- 契约检查没有比对 `attention` 枚举与 shared 是否一致（这次两处都手工同步了）。
- 邮编与州的核对只在小程序端做，服务端和后台改址没有同样的检查。
- “超时未发货”没有扣除日本法定节假日：黄金周、年末会提前报超时，偏严。
- 后台订单页的状态页签计数是全站数，不随“按买家筛选”变化。
- 小程序“我的”页没有客服入口，因为模拟环境没配客服信息。上线前要配好，否则售后页“需要补充照片请联系客服”无处可联系。

## 7. 需要你决定的（小程序界面冻结，我没有改）
1. 区块小标题用英文（ITEMS / AMOUNT / DESCRIPTION / GUARANTEE / SHIPPING TO 等），有几处没有对应的中文标题。是否改成中文或中英并列？
2. 价格副行“≈ $47.63 · ≈ ¥346.70”里，¥ 指人民币，但紧挨着日元价格，容易误读。是否改成“346.70 元”？
3. 结算页“已超过单笔上限，请分两单下单”用的是灰色提示字，是否改成醒目色？（底部栏已有一份深色提示）
4. 支付页倒计时“请在 29 分 56 秒内完成支付”是页顶的小灰字，是否加强？
5. 商品标题允许 255 字。实测 255 字标题会占满详情页首屏，价格被挤到下面。是否在后台提示“标题建议 60 字以内”，或在详情页折叠超长标题？
