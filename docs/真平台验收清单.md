# 真平台验收清单（代码审查之外的那一半）

> 建立：2026-10-16。背景：到此为止所有验证都在本机完成，多轮代码审查后剩下的风险集中在"从没碰过真平台"。
> 本清单把这些项**集中到一处**，每条写清在哪个平台、做什么动作、看到什么算过；验收由脚本能自动做的就自动做，做不了的写明人要做什么。
> 以后不论谁改代码（本人、AI 助手、并行工具），**验收标准是同一张表**，不再靠人读代码判断"应该没问题"。
> 怎么做：逐步操作见 [操作手册-staging搭建与小程序真机-新手版.md](操作手册-staging搭建与小程序真机-新手版.md)（含示例与排错）。
> 规则：验过的在「状态」列写日期与依据（报告文件 / 截图 / 日志行）；没验过的保持空，不许写"应该可以"。

## 0. 自动化入口（先跑这些，再看人工项）

| 命令 | 验什么 | 前提 | 结果在哪 |
|---|---|---|---|
| `npm run gate` | 代码对不对（本机 / CI 每次提交） | 本机 Postgres 16 | `.gate/gate.log` 尾行 `gate-exit=0` |
| `npm run stripe:rehearsal -- --channel mock` | 下单 → 付款 → 退款整条链在本机走通（不需要 Stripe 账户） | `npm run dev` 在跑 | `var/rehearsal/<时间>-mock.md` |
| `npm run stripe:rehearsal -- --channel stripe` | 同上，但走 **真 Stripe 测试模式**：真会话、真回调、真退款、真拒付。人只做一件事：在托管页输测试卡号 | `.env` 有 `sk_test_` 密钥；Stripe CLI 已 `stripe login` | `var/rehearsal/<时间>-stripe.md` |
| `npm run smoke -- --base https://<api 域名>` | 已部署环境活着且配置齐（健康、条款、商品、鉴权、管理员登录、每日对账无系统类异常） | 环境已部署；管理层要 `SMOKE_ADMIN_*` 三项 | 终端尾行 `smoke ok` / `smoke FAILED`；GitHub Actions `smoke` 每天自动跑 |
| `npm run mutation` | 严格档纯函数模块的测试**抓不抓得住错**（覆盖率只能证明跑过）。自研小工具（Stryker 在 vitest 5 下跑不出结果，见 scripts/mutate-lib.ts） | 目标文件无未提交改动 | `var/mutation/<时间>.md`；GitHub Actions `mutation` 每周自动跑 |
| `node scripts/api-fuzz.mjs` | 契约驱动的畸形输入探测（只读） | 本机服务在跑 | 终端 |

## 3. 进入日常后（上线运维手册 §5、上线总手册 §10）

- 每天：Actions `smoke` 绿；告警邮件没有新 error。
- 每周：Actions `mutation` 绿；Dependabot 的 PR 合掉；Stripe 后台看拒付。
- 每月：恢复一次备份到临时库；对账报告过一遍。
