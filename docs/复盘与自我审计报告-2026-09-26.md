## 三、自我批判

**做得好的**
1. 把"骨架退役"当成**重新指派守护**（28 条逐条标注去向），而不是删文件删测试。
2. 缺陷注入常态化：本轮 3 次注入（断开端点→作业接线 / 摘 128 校验 / 摘 dangling 扫描）**全部变红**，还原复绿。
3. 单一出处意识到位（seed helper、`scopeKey`、D-46 SQL）。
4. 契约豁免清单清空后，骨架"复活"会被比对器当场抓住——机制闭环而非口头承诺。

**做得不够好的**
1. **违反自己立的规矩**：为了"测试好写"，在生产模块导出测试钩子 + 模块级状态。这正是我在 ADR-29 里写的"注释与事实不符 = bug"的同构错误——产品代码里焊了测试脚手架。
2. **把 flaky 当抖动**：dev-up 清理超时第一次出现时，我用"单跑绿 = 环境抖动"把它放过了。**单跑绿不能证明全量下不红**，这是 §2 第 38 条同形态的第二次。
3. **对账的出口只到日志**：欠账①被评为致命级，落地形态却是"要看日志才知道"。日志没人盯 = 没出口。
4. **演示页死链留着**：我用"改写属 I2 范畴"正当化了它，但结果是仓库里有一个点了就 404 的页面。
5. **证据感错觉**：1453 条绿容易被当成"覆盖充分"。实际未覆盖的语义包括：对账窗口边界（47h/49h）、金额/币种边界组合、限流跨实例行为。

## 七、最终评价

**过程**：A-。红灯纪律、缺陷注入、单一出处、一单元一 commit 在本轮是**真的在跑**（3 次注入全红、路由比对器抓骨架复活、F10 规则拦住 `new Date`）。扣分项是我自己违反了一条自己写的规矩（生产模块测试钩子），以及第一次把 flaky 当抖动放过——两处都在自审里被抓出并修掉，但"被自审抓出"说明写的时候没想。

**产物**：B+。U6c 的退役是干净且可回滚的（每条守护都重新指派）；U7b 把致命级欠账①变成了每天会响的东西。扣分在**可见性最后一公里**：对账只到日志、演示页是死链、契约跨仓未同步——三件事的共同点是"技术上完成了，人的那一环没接上"。

**能不能进 I2**：能，但**必须带着 R-b / R-a / R-c 三张单子进**，不能假装它们不存在。
