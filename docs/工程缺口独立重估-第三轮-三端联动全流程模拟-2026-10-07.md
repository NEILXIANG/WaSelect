### 1.2 实测通过的（压缩）

- **地址**：20 条上限 40917 在锁内生效；emoji / 日文 / 非 E.164 电话 40002；ZIP+4 放行。
- **报价 / 建单**：51 行、重复 SKU、qty 0 / 1.5 → 40001；超重 40912；`expected_total` 不符 40905；旧条款 40011；别人的地址 40400；坏邮箱 40001；同幂等键重放同一张单、同键异体 40908、幂等键按用户隔离；第 4 张在途单 40913；取消回补库存。
- **并发**：3 人抢 1 件 → 1 成功 2×40901、库存 0；5 次并发建单只放 3 张；取消与付款同时 → 取消赢、付款 40902、库存回补一次；发货与改址同时 → 发货赢、改址 40902；两管理员同时整单退款 → 一条 refunding 一条 refunded 事件（mock 下两边都 202；Stripe 下第二个会拿 409，见 §2 P2-14）；两笔各 60% 的部分退款同时 → 一笔 202 一笔 40001。
- **支付生命周期**：过期单由 tick 关掉并回补；有 initiated 支付行的过期单多等 5 分钟宽限；迟到付款 → 200 + `late_paid` 凭据、重放不重复、坏签名 401；管理端列表标 `late_paid`、可全额退款且不重复回补。
- **退款矩阵**：部分 1/3 → 超额 40001 → 负数 / 字符串 40001 → 整单退余额 refunded → 再部分退 40902；completed 单可部分退、整单 40902（设计）；拒付中发货 40909 / 整单 40907 / 部分 40907；解除后可发货。
- **拉黑**：在途单连带取消、已付单不动、旧 token 立即 403、已拉黑列表、解除、审计两行。
- **配置事故**：汇率 >72h → 50003；汇率录反（147.5）→ 40001；运费表替换为空 / 只剩一档 → 40001 拒（整表替换有校验）。
- **安全探测**：读 / 删别人的资源 40400；买家访问管理端 403；缺幂等键 40001；匿名刷报价第 9 次 429；管理员错 7 次口令后正确口令也被拒；NUL 字节路径 302 到失效页（非 5xx）；150KB 请求体 400；日志 0 处 PII。
- **作业**：手动触发每日作业 202、错密钥 401、重复触发不叠跑；对账落一行 `reconciliation_runs`。

## 4. 三端一致性（契约 ↔ 服务端 ↔ 小程序 ↔ 管理端）

**请求字段**：全部一致（幂等键、`qty` 整数、`expected_updated_at` 形状、带偏移时间串、`amount_minor` 整数）。仅三处前端缺预检：小程序搜索无 64 字上限、管理端登录无 12 位提示、支付页 `country` 写死 US。

**响应字段**：服务端省略可选字段一律**整键省略**，两端全部用 `typeof` / `Array.isArray` 守卫，**未发现省略即崩**。不一致处：

| 端点 / 字段 | 问题 | 哪端 |
|---|---|---|
| `AdminOrder.events[].status` | 服务端写 `partial_refunded` / `partial_failed`，管理端无文案 | 管理端 |
| 订单状态文案 | shared `ORDER_STATUS_DISPLAY` 自称"两端同一套"但**零消费方**；小程序 / 管理端各一份且互不相同（`paid`：待发货 / 已付款 / 待发货；`completed`：已签收 / 已完成；`expired`：已关闭 / 已超时关闭 / 已过期） | shared 死码 + 两端漂移 |
| 分类文案 | `daily` → 管理端"日用杂货" / 小程序"生活百货"；管理端 `PRODUCT_CATEGORY` 自抄一份 | 两端 |
| `POST /orders/{id}/cancel`、`POST /admin/orders/{id}/address` | 契约"200 无体"，实回 `{ok:true}` / `{order_id,address}` | 契约 |
| `AdminOrder.payments[].created_at` | 实回、契约未列（0.6.27 自认"仍缺"） | 契约 |
| `/orders/{id}/pay`（mock，非审核） | `auto=false` 且无 `pay_url` → 小程序 `payPlan` 判 `unsupported`，而 `/pay/channels` 仍列出 mock | 仅开发期 |
| `Currency` | 契约 `PaymentIntent.charge.currency` 少 CNY；小程序 `CHARGE_CURRENCY_ORDER=['JPY','USD']` 写死 | 当前无 CNY 通道 |

**错误码**：服务端会抛、契约没列（契约比实现宽松）——`GET /products` / `GET /orders` 的 40001、`GET /orders/{id}` 的 40400、`PUT|DELETE /addresses/{id}` 的 40001 / 40002 / 40400、`POST /orders/quote` 的 40001 / 40401 / 50003 / 50004 / 40916、`…/sync` 的 40001。契约登记但服务端从不以 JSON 抛：`40102`（短链失效走 302）。客户端能收到但无专门处置：见 §2 P2-40 / P2-43 / P2-49。

**枚举**：OrderStatus 10 态 / DisputeStatus 4 值 / PaymentChannel / ComplianceTag 11 值 / PartialRefund.status 5 值 四方一致；DisputeStatus 未进 shared（服务端与管理端各抄）。

**状态 → UI**：十个状态在小程序 / 管理端均有文案，管理端四个按钮的 gate 与服务端 `shipGuard` / `refundGuard` / `addressGuard` / `partialRefundGuard` 逐态对得上；唯一设计风险是小程序支付页**未知状态当可付**。

**金额单位**：JPY 整数、最小单位整数、主单位输入三处口径全部一致，未发现"一端发主单位、另一端读最小单位"。

## 5. 数据模型与运维（补充 §2 之外的结论）

- **通过**：所有金额列 BIGINT 最小单位、比率 NUMERIC、业务时间全 TIMESTAMPTZ；状态域 CHECK 与 shared 枚举一致、所有写入值在域内；FK 全 NO ACTION 且代码无 DELETE 路径、dev 库 0 孤儿；append-only 四表触发器在位且代码无 UPDATE / DELETE；幂等键 `${userId}:${route}:${clientKey}` + 租约栅栏（dev 库实证）；全部 FK 列有索引。
- **`order_events.status` 实为 VARCHAR(20)**（AJ-383 注释写 16，错了），19 个写入值最长 16；伪状态无长度守卫，下一个 `partial_refund_pending`（22 字）就是 22001 → 500。
- **`admin_audit.action` 余量 12 字**：最长路由 `POST /admin/orders/:id/partial-refunds/:refundId/sync` 52 字，`slice(0,64)` 静默截断。
- **数据保留**：`webhook_events` / `order_address_history` 无清理；匿名化（AJ-292）只有口径没有代码，且 `users CHECK(openid OR email)` + `UNIQUE(openid)` 意味着匿名化要先设计占位值。
- **种子**：`hs_code VARCHAR(10)` 只校验长度——美国 HTS 10 位带点写法（13 字）存不进且无提示。

## 6. 对接支付机构前的 Top-10

1. **Stripe 回调失联静默**（P1-1）——唯一防线是上线日发一条测试事件，没有持续监控。
2. **启动不校验迁移**（P1-2）——本轮实测踩到：健康检查全绿、建单全 500。
3. **汇率过期无预警 + 漏录一个展示币种全店停售**（P1-9 / P1-12）——周末两天就能撞上。
4. **`mark-paid` 取到已作废支付行**（P1-3）——连点两个通道 → 钱扣了单不落账。
5. **管理端登录可被锁死 + 单因素账号直接退款权**（P1-5 / P2-53）——Cloudflare Access 或 TOTP 必须在真钱之前。
6. **机构侧退款 / 失败回调不落账也不进对账**（P1-4）——Stripe 后台一次手退就账实不符。
7. **发货后运单号不可改 + 无取消未付订单接口**（P1-10 / P1-11）——运营两件最常见的"手滑"都没有出口。
8. **买家通知链极脆**（A6 / P2-11 / P2-12）——邮箱可选、订阅消息未做、迟到付款与部分退款买家都看不见，而结算页承诺"会发邮件"。
9. **CSV 在 Excel 里被数字化**（P1-8）——报关清单 ZIP 前导零丢失是真实错单。
10. **daily 撞发布窗口 / DB failover 未实测 / 上传 OOM**（P2-19 / D2 / P2-16）——都是"一个月内会遇到一次"的运维形态。
