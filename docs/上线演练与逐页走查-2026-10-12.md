# 空库上线演练与两端逐页走查（2026-10-12，第二轮）

> 接在《上线前服务端严格测试》《两端输入测试》之后，换两个角度再查一遍。
> - **服务端**：不再复制模拟库，而是在**全新空库**上按《上线运维手册》从头演练首次上线，同时检验手册本身。
> - **两端**：后台（桌面 1440 宽）与小程序（开发者工具）逐页截图，逐个控件看布局、文案和信息是否够用。

## 1. 空库上线演练

演练环境：
- 代码：`npm run build` 打包后的代码。
- 配置：`NODE_ENV=production`，审核期配置（`REVIEW_MODE=on` + mock）。
- 数据库：全新库 `japan_shop_launch`。生产闸门不许数据库指向本机，所以经一个只接受本机来源的转发器连库。

按手册的步骤走：
1. 跑迁移（重跑一次确认幂等）。
2. 启动时用 `ADMIN_EMAIL` 自动建出第一个管理员。
3. 用 CLI 开通 TOTP。
4. 不带 TOTP 登录（被拒），带 TOTP 登录（成功）。
5. 在后台建商品、上架、录运费表和汇率。
6. 把审核商品编号写进配置并重启。
7. 买家下单，审核期自动确认付款（测试单默认在后台列表里隐藏）。
8. 发货：测试单被拒，后台已提前写明原因。
9. 触发每日作业。

| 发现 | 处理 |
|---|---|
| 迁移后运费表、汇率表都是空的，买家报价一律 500「运费不可计算」；**手册没有"开张前先配运费与汇率"这一步** | 手册新增 1.5"开张前的业务配置"，并在 1.4 加一条核对项 |
| `REVIEW_SKU_ID` 必须在启动时就给，可那时库里还没有商品；编号填错（商品不存在、没上架、缺货）时，**启动、对账、设置页都不报** | AJ-505 上线就绪检查：启动时跑一次（error 进 Sentry），每日对账加第十四类 `launch_not_ready`，逐条写人话；手册写明审核商品编号的先后顺序 |
| 没有任何汇率时没人报（原有对账只报"快过期"），而银行卡按美元收款 | 归入同一项检查（缺哪个币种就报哪个） |

补齐后再启动，日志里是 `launch_ready`；下单、付款、对账全部通过。

## 2. 后台逐页走查

| 页面 | 发现 | 处理 |
|---|---|---|
| 订单列表 | "采购信息"一列只有日文原名、JAN、采购来源，**没有中文名和件数**，采购员看不出要买几件 | 每个商品先写"中文名 × 件数"，下面再接采购依据；表头改为"商品 / 采购信息" |
| 订单详情 | 收货地址用中文逗号拼接，与客户页、打印面单不一致；**没有收件人电话** | 改为美国写法（City, ST ZIP），新增"收件人电话"一栏 |
| 设置 | 没填的项一律写"上线前请配置"：审核模式关着时审核商品和截止日根本不需要，包邮门槛不设就是不包邮，客服微信、告警邮箱有替代项时可以不填 | 按上下文说明；审核商品显示"「名称」· 状态 · 库存"（契约 0.6.86） |
| 运营日志 | 对账示例写 `ord-70d4257d…` / `pay-6cfc82a4…`，运营在后台找不到这些编号；"上线配置缺项"的整句说明被截成 16 个字 | 服务端读取时换成订单号（`sample_orders`，契约 0.6.87）；整句说明原文全部显示 |
| 商品编辑 | "编辑标签"输入框没有标签（读屏只读出"编辑文本"） | 加 `aria-label` |
| 工作台、客户、商品列表、风控 | 没有问题 | — |

## 3. 小程序逐页走查

走过的页面：首页、商品详情、购物车、结算、订单列表、订单详情（已发货 / 已送达含售后 / 已退款）、售后申请、地址簿、我的、条款。

| 页面 | 发现 | 处理 |
|---|---|---|
| 订单列表 | 卡片只有首件商品名 + "共 2 件"，两种商品的单看起来像同一件买了 2 份 | 服务端给 `line_count`（契约 0.6.88）；超过一种时写"首件名 等 N 种商品"，首件名过长先截到 20 字，保证后缀不被两行省略号截掉。只改文字，不动样式（小程序界面冻结） |
| 其余页面 | 金额、进度条、售后结果、地址写法、客服信息都对得上 | — |

模拟数据造成的现象不算缺陷，未改：
- 订单号都以 261012 开头：回填数据时下单时间被改早了。
- 部分商品缩略图与名称对不上：模拟库按分类配的占位图。
- 商品介绍里出现"测：……"：模拟数据本身的文字。
