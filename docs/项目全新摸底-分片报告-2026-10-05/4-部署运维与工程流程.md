## 0. 一页结论

1. **部署"图纸"很完整，但实际一次都没部署过。** `render.yaml` 声明了 API web + 每日 cron + admin 静态站 + PG16（render.yaml:14-283），CF Pages 和微信域名各有一份受门禁约束的清单。可是没有任何 staging，路线图里每个"首次部署后验一次"的项（B1-余 / B2-余 / B3-余 / B4/B5-余、TRUST_PROXY_HOPS、/healthz 平台行为）全部未验。**最大的上线风险不在代码，而在"第一次真部署"本身。**
2. **可观测性基本没有。** Sentry 只有配置键、没有使用方（config.ts:574；server/src 里没有任何 Sentry import）。日志只写到 stdout（logger.ts:116-117），没有接任何可检索的日志平台（docs/代码注释规范与日志体系设计.md:136 自己也承认）。生产出了异常没人会被叫醒，调度器停摆最长要约 24h 才被每日 cron 发现（render.yaml:216）。
3. **管理端登录口目前对公网裸露。** `ORIGIN_VERIFY_SECRET` 默认空、render.yaml 也没有这个键，main.ts:155-166 只在启动时打一条 error 日志。"管理端在 Cloudflare Access 之后"这个设计前提，在当前配置下并不成立。
4. **CI 是否真在跑，无法确认。** ci.yml 本身写得不错，但仓库是私有的（GitHub API 返回 Not Found），本机也没有 gh CLI。另外 Render 默认"推到 main 就自动部署"，并不等 CI 结果【推断】。现在每天 10~50 次提交，还有两个 AI 工具同时往 main 推，上线后等于每次提交都是一次生产发布 + 一次迁移。
5. **投入结构严重偏向"审查 / 注释 / 文档"。** 源码约 4.4 万行，其中约 43% 是注释行；测试 6.6 万行，是源码的 1.5 倍；docs/ 有 3 万行，光《自主决策记录》一份就 13,464 行 / 1.4MB / 364 条。386 次提交里约 241 次是审查、修复或 AJ 编号类，标 feat 的只有 95 次。路线图给"我"排的下一步第一项，仍然是"第五轮全量逐行重读"（上线路线图:204-205）。**对一个还没上线、只有一人维护的项目，这个比例不可持续。**

### 1.1 上线必须项的解决方案（P0）

| # | 方案 | 工作量 |
|---|---|---|
| A | **先建一个 staging**：同一份 Blueprint 复制成 `waselect-api-staging` / `-pg-staging`，库用最小档，NODE_ENV=staging。在 staging 上一次性验完路线图里的所有"首次部署后手验"项：healthz 平台行为、XFF 层数→TRUST_PROXY_HOPS、cron 私网、admin 深链和 CORS、R2 真桶、CF Pages 302。验完回写 `@measured`。staging 平时可以挂起省钱 | 1.5–2 |
| B | **部署要等 CI 绿**：在 Render 设成"checks 通过才部署"（或关掉 autoDeploy，改用 GitHub Actions 在 gate 绿后调 Deploy Hook）。同时**把发布分支和开发分支分开**：AI 工具推 `main`，生产只跟 `release` 分支或 tag | 0.5 |
| C | **ORIGIN_VERIFY_SECRET 上线前必须配**：API 与 admin 都挂到 CF 自定义域，CF Transform Rule 注入 `x-origin-verify`，admin 域套 Cloudflare Access（邮箱 OTP 即可）。render.yaml 补这个键，并按 main.ts:152-153 自己写的升级路径，把它改成生产拒启规则 | 0.5–1 |

| F | **外部探测 + cron 失败告警**：UptimeRobot / Better Stack 每分钟探 `https://api.../healthz`；每日作业成功后 ping 一个 heartbeat URL（healthchecks.io），没 ping 就告警。代价是 cron startCommand 多加一个 fetch | 0.5 |
| G | **备份**：确认 Render PG 档位的 PITR 保留期；另加一个每周 `pg_dump` → R2 的异地副本（可以复用现有 cron 机制）；**上线前做一次恢复演练**（恢复到 staging 库）并写一页手册 | 1 |
