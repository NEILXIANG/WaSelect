# ADM 分片：管理端与运营能力（全新视角摸底，2026-10-05）

> 评判标准：**4 位合伙人（以非技术为主）能否只靠管理端完成日常运营，而不需要开发者改库 / 改代码 / 进平台控制台**。
> 证据标注：【码】= 已读代码确认；【推断】= 根据代码结构或缺失推出，未运行验证。
> 只读分析，未运行任何 npm / vitest / 服务。docs/ 下审查报告与路线图只当线索。

---

## 0. 一句话结论

管理端已经覆盖了**"上架 → 收款 → 采购清单 → 录单号发货 → 全额退款 → 拒付处理"这一条最短闭环**，单个动作的防错做得很细（乐观锁、两步确认、改前值审计）。
但离"合伙人自己能维护"还有三类明显缺口：
1. **能看但看不全**：没有任何报表、看板或导出；审计日志、对账结果、用户行为数据都只存在于数据库或平台日志里，管理端看不到。
2. **一半配置不在管理端**：关税率、目的国、分类、支付通道开关、审核模式、管理员账号都只能改库、改代码或进 Render 控制台。
3. **出了问题无人知道**：没有告警通道（Sentry 只有变量没有接线），对账结果只写进日志，备份与恢复没有手册。

## 3. 管理端可用性

| 问题 | 现状与证据 | 影响 |
|---|---|---|
| 权限模型 | 只有一个角色，见 1.5 | 不能按岗位分权限；共用账号时审计会失真 |
| 会话过期 | JWT 12 小时（`auth.ts:62`），没有续期，也没有过期前提醒；收到 40101 直接回到登录页（`App.tsx:64-68`），**正在编辑的商品表单会因为组件卸载而丢失**【码：`!token` 分支直接渲染 LoginForm，`ProductFormPage` 被卸载】 | 录到一半的商品要重新录 |
| 刷新 / 后退 | 页面切换只用 state，不用路由（`App.tsx` 文件头注释）；刷新会回到商品页，不能把某个订单的链接发给同事 | 协作时只能说"你搜单号 xxx" |
| 错误提示 | 业务错误码有中文映射；商品保存时字段级错误不能透传给前端（1.1） | 偶尔出现"保存失败"却不知道原因 |
| 并发编辑 | 商品有乐观锁 ✅；订单写操作有行锁和状态守卫 ✅；**Banner 和运费表没有版本校验**（grep `expected` 无结果），后保存的人会覆盖先保存的人【码】 | 两个人同时改运费表时，后保存的会静默覆盖 |
| 多人协作 | 没有"谁在处理这单"的标记，也没有备注；审计里有 actor，但界面看不到 | 两人可能对同一单重复操作，状态守卫只能挡住其中一部分 |
| 移动端 | 有 viewport meta，但 `app.css` / `tokens.css` 里**一条 `@media` 都没有**【码】；表格页在手机上会横向溢出【推断】 | 陈丽琴在日本店里或打包现场用手机操作会很吃力 |
| 语言 | 只有中文；用户 2026-10-02 明确"管理端只需要中文"（路线图:15） | 遵从这个决定；南雲国萍如果要用，需要再评估 |
| 部署 | Render 静态站（`render.yaml:237-241`），有 localhost 构建闸门 ✅；PRD 写"管理端放在 Cloudflare Access 之后"（D-52），但 render.yaml 里没有对应配置，只在代码注释和启动告警中提到（`main.ts:143-161`）【码】 | 上线时需要人工在 Cloudflare 上配置，没有 IaC 守护 |

## 5. 问题清单、解决方案与工作量

人日按单人估算（含测试，遵守项目的门禁纪律），**数字偏保守**。优先级：**P0 = 上线必须**，**P1 = 上线后一个月内**，**P2 = 之后**。

| # | 问题 | 方案 | 人日 | 优先级 |
|---|---|---|---|---|
| A1 | 没有告警，对账结果没人收到 | 接入 Sentry（error 级日志和未捕获异常）。每日对账结束后，有异常时**发一封邮件或企业微信 / Slack Webhook** 给运营负责人，并发送汇总 | 1.5 | **P0** |
| A2 | 只能有一个管理员，4 人共用会让审计失真 | 增加 `scripts/admin-create.ts`（与 admin-password 同构），给每位合伙人建独立账号；界面版本见 B4 | 0.5 | **P0** |
| A3 | 备份与恢复没有手册 | 实测 Render PG 的备份策略并写进 `@measured`；写一页恢复手册，演练一次恢复到 staging；另加一个每周 `pg_dump` 到 R2 的 cron 作为第二道保险 | 1.5 | **P0** |
| A4 | 审计日志、对账异常在管理端看不到 | 增加"运营日志"页签：`GET /admin/audit`（按 actor / 动作 / 时间筛选），以及 `GET /admin/reconciliation/latest`（读 `job_runs` 或单独落表的结果） | 2 | **P0** |
| A5 | 退款不回补库存 | 退款落定时回补库存（与关单走同一函数），或者在退款弹窗里明确提示"请手动回补库存"。这是需要拍板的业务口径 | 0.5 | **P0** |
