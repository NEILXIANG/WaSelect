# 两端带数据逐状态走查（2026-10-12，第三轮）

> 接在《上线前服务端严格测试》《两端输入测试》《上线演练与逐页走查》之后。
> 前两轮的盲区是"**没有数据就走不到的状态**"：待付款、退款卡住、部分退款在途、拒付胜诉 / 败诉、被拉黑的买家、全新买家、未开始 / 已结束的 Banner、改价与下架后的购物车……
> 这一轮先把这些状态造出来，再在后台（浏览器）和小程序（开发者工具自动化）里逐状态点到每个按钮、填过每个输入框。

## 1. 造数据

只在模拟库 `japan_shop_sim` 上做，造之前先整库备份。造出的状态：

| 状态 | 用在哪 |
|---|---|
| 待付款订单（30 分钟内） | 小程序订单详情底栏、后台"取消订单" |
| 全额退款卡在"退款中" | 后台重试退款 |
| 部分退款一笔处理中、一笔失败 | 后台金额区、"同步"按钮 |
| 拒付胜诉 / 败诉各一单，另有进行中的拒付 | 风控页、订单待处理筛选 |
| 有拒付的买家、被拉黑的买家、全新买家 | 小程序结算 / 地址簿 / 空态，后台客户页 |
| 还没开始、已经结束、已停用的 Banner | 后台 Banner 列表、小程序首页 |
| 购物车里的商品被改价、被下架、库存不够 | 小程序购物车与结算 |

此外，在小程序里实际下了一单、付了款，提交并在后台驳回了一条售后。

## 2. 发现与处理

### 小程序

| 页面 / 状态 | 发现 | 处理 |
|---|---|---|
| 订单详情 · 待付款 | 底栏同时有"取消订单"和"去付款"时，"应付"两个字被挤成竖排，金额断行 | 金额区改为上下两行，标签不折行（4094e7c） |
| 结算 · 被拉黑的买家 | 取地址被拒（40301）后提示"请点重新加载"，页面上并没有这个按钮；地址簿还显示"新增收货地址"，点了也存不了 | 写明"账号已被限制使用"，地址簿隐藏新增按钮（4290091） |
| 购物车 · 改价 | 商品改价后，那一行只显示新价，买家不知道价格变了 | 那一行写"价格已由 A 调整为 B"（2c79a88） |
| 购物车 · 下架 | 报价时提示"有商品已下架"并附带报障编号，买家不知道是哪件 | 写出商品名，不带报障编号（2c79a88） |

已走查、未发现问题：售后提交（空提交、只填空格、正常提交）、售后被驳回后的显示与"再次申请"、结算 → 付款页 → 付款成功、从付款页返回（回到购物车，已下单商品已移除，不会重复下单）、首页 Banner（只出现展示中的 4 条）、新买家的"我的 / 订单 / 地址簿 / 购物车"空态。

### 后台

| 页面 / 状态 | 发现 | 处理 |
|---|---|---|
| 订单详情 · 未付款 | 操作按钮叫"修正发货信息"，打开后要再切到取消表单 | 按钮直接叫"取消订单…"，打开就是取消表单（399cdc5） |
| 订单详情 · 退款中 | 重试全额退款时又要运营重新选原因，可能和第一次填的不一样 | 写明"沿用第一次的退款原因：…"并直接用它（AJ-506，b61940d） |
| 订单详情 · 部分退款 | 金额区只有实付，看不出已经退了多少、还有多少在途；点"同步"后只说"已提交" | 金额区增加"已部分退款 / 部分退款处理中"；同步后说出查到的结果（a0ce593） |
| 订单详情 · 商品行 | "× 2 2,470 日元"看不出是单价还是小计 | 写明"单价"，多件时下一行写小计（64a91f4） |
| 订单详情 · 售后 | 没写处理说明时结案按钮是灰的，但不说为什么，运营点了没反应 | 按钮旁灰字说明"写好处理说明才能结案"（1be7149） |
| 订单列表 · 待处理 | 六类待处理只有名字，要逐个点开才知道有没有单 | 每一类带单数，0 单收淡；计数与点进去的列表同一过滤条件（5b0f791） |
| 风控 · 拒付列表 | 已结案的拒付行按钮也叫"处理"，点开其实只是拉黑；拉黑面板写内部用户编号 | 按钮写实为"拉黑买家…"，面板写姓名与邮箱（4b7f226） |
| 风控 · 拉黑 / 解除拉黑 | 确认弹层仍写内部用户编号；没填原因时提示飘在右下角、光标不动；点"取消"或换一个人后，上一个人的原因还留在框里 | 弹层写买家姓名与邮箱；提示标在框下并聚焦；取消或换人时清空原因（b647c48） |
| 首页 Banner | 还没开始、已经结束的 Banner 状态也写"启用"，运营以为买家看得到；只填了开始时间时显示半截 | 状态按当前时间写"展示中 / 未开始 / 已结束 / 停用"（与服务端闭区间同口径）；只有一端时写"… 起 / 至 …"（faa4e2b） |

已走查、未发现问题：商品分类（有商品的分类删除按钮禁用并悬停说明原因）、客户列表与详情（被拉黑买家显示"已拉黑"）、运营日志（"编辑分类 —"是 AJ-497 修复前的旧记录）、工作台待办计数与订单页一致、各待处理筛选的列表与计数一致。

## 3. 关于小程序开发者工具里的 409

联调时控制台出现的 `POST /api/v1/orders/quote 409` 是这一轮**有意制造的超库存报价**（40901），购物车已按预期提示"库存不足"并给出可买数量，不是缺陷。

## 4. 验证

- 每项修复先写会失败的用例、确认变红，再改实现；全部在页面上（浏览器 / 开发者工具）复核过。
- 严格档只有 AJ-506（退款原因沿用），已入《自主决策记录》并做过缺陷注入；其余为轻量档。
- 全量 gate（`npm run gate:log`，HEAD 5b0f791）：`gate-exit=0`，5857 条通过（另 1 条预期失败）。
