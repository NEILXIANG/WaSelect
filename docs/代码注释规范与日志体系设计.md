# 代码注释规范与日志体系设计

> 状态：已定 ｜ 版本：v1.0（2026-09-22）｜ 适用范围：`jp_project` 全部代码（server / miniprogram / checkout-static / admin-web；注释规范的**机器强制**范围更窄，见 §4）；2026-09-28 一致性审计校正（AJ-176）
> 来源：用户 2026-09-22 明确要求——**注释要详细，看注释就知道逻辑、缺点和优点**；**出问题能靠日志定位，必须能捕获代码运行信息与用户操作行为，不能缺有价值的分析数据**。
> 配套：《测试策略与验证门禁》《可扩展架构设计》《技术文档 v0.5》《工程框架 v0.5》

## 0. 一句话结论

> **注释写"为什么这么写、放弃了什么、还有什么坑"**（不是复述代码）；**日志做到"任何一个问题都能回答：谁、什么时候、哪个请求/订单、做了什么、结果如何、耗时多少"**，运行日志、业务审计、用户行为三条流分开且用同一个 `trace_id` 串起来。

# 第一部分：代码注释规范

## 1. 三条原则

| # | 原则 | 说明 |
|---|---|---|
| **C-1** | **注释回答 why，代码回答 what** | 不写"这里循环遍历订单"这种复述；要写"为什么必须先锁再查、为什么不批量、为什么阈值是这个数" |
| **C-2** | **缺点必须写** | 每段非平凡实现都要有 `@limitation`（已知缺陷/未覆盖场景）+ `@tradeoff`（放弃了什么、为什么）。**只写优点的注释视为不合格** |
| **C-3** | **注释可溯源** | 关键决策必须 `@see` 到 ADR / 技术文档章节 / 决策编号（如 `@see ADR-25`、`@see D-46`），让后来人知道这是有依据的，不是随手写的 |

## 2. 三层注释结构

### ① 文件头（每个文件必写）

```ts
/**
 * 职责：运费分档报价（重量 → 价格）
 * 边界：只做"取档 + 取整"，不做汇率换算、不做关税计算（关税见 pricing/duty.ts）
 * 依赖方向：domain 层，禁止 import 任何 adapter（ESLint no-restricted-imports）
 * @see 技术文档 v0.5 §2.5（口径）、D-46（取档方向事故）、ADR-28（扩展性：dest_country 维度）
 * @limitation 当前只按重量分档，未考虑体积重与偏远地区附加费（P2）
 */
```

### ② 函数/方法 JSDoc

标签固定集合：`@param @returns @throws @sideeffects @perf @security @see @limitation @tradeoff`

**示例（本项目真实高风险点）**：

```ts
/**
 * 按包裹总重取运费档位（整数円）。
 *
 * 逻辑：`max_weight_g` 是"档位上限（含）"，所以必须取**第一个 max_weight_g >= 包裹重**的档（向上取档）。
 * @see D-46 —— 模型曾长期用 VLOOKUP(…,TRUE) 向下取档，每单少收 900–1,000 円且静默不报错，属运营事故级。
 *
 * @param weightG 包裹实重（含包材，PACKAGING_WEIGHT_G=250 + 商品重量×件数）
 * @returns 该档 price_jpy（整数円）；无匹配档抛 NoRateError（调用方映射 50004）
 *
 * @tradeoff 单一 SQL 而非 ORM 条件构造：语义钉死在 SQL 里，杜绝"实现与契约漂移"（D-46 发现的第 2 个问题）。
 *          代价：换库要改 SQL，但本项目不换库。
 * @limitation 未做体积重（ dimensional weight ）：抛重包裹（保温杯空箱）会低估运费 → 每单可能少收一档。
 *             缓解：包材重量 250g 已含缓冲；真出问题在 shipping_rates 调档，不改代码。
 * @perf 单条主键范围查询 + LIMIT 1；加 (carrier, dest_country, max_weight_g) 索引后可走索引扫描
 */
```

### ③ 行内块注释（决策点才写）

只在这几处写：非常规写法、踩过的坑、看起来可优化但不能动的地方、魔法数字来源、并发/事务边界。

```ts
// 必须在事务内取 advisory lock：Render 多实例/重启时会有多个调度器，靠 Postgres 锁保证同一时刻只有一个 tick 生效（D-43）
// ⚠️ 不要用 pg_try_advisory_lock（会话级）：连接复用会让锁永不释放，必须事务级（D-45）
await sql`SELECT pg_try_advisory_xact_lock(${LOCK_KEY})`;

// 30 分钟是最短可设值：Stripe Checkout Session 的 expires_at 最短 30 分钟，低于它会被拒绝（D-49）
const expiresAt = max(addMinutes(now, 30), order.expiresAt);
```

## 3. 缺陷与待办登记（强制）

- 禁止裸 `TODO` / `FIXME` / `XXX`。格式：`// TODO(#I1-07, owner=向, due=2026-10-05): 体积重未处理，见 @limitation`
- 每条 TODO 必须同时在《任务看板》有对应行，注释里写编号，双向可查
- `@limitation` 允许无期限（属于"已知但不做"），但必须在文档中留痕，避免后来人以为遗漏

## 4. 同步纪律

- **改代码不改注释 = bug**（review 必查项，列进 DoD）
- 注释里引用的 ADR / 决策编号若被取代，必须同步改（`grep -E "ADR-1[0-9]|D-[0-9]+"` 定期扫一次）
- 注释强制器：**不引入 eslint-plugin-jsdoc**（AJ-17：本机实测 jsdoc 与 typescript-eslint 同进程 import 会被资源看门狗 SIGKILL，且其规则只是 warn 级便利项）；现行强制器是 `test/lint/comment-header.lint.test.ts`（LM 层，随 `npm run test:lint` 跑）——它验三条形态底线：有文件头块注释、写了 `@why`、写了 `@limitation` 或 `@tradeoff`；只验"标记在不在"，内容质量仍靠 review（CLAUDE.md H3）。⚠️ 扫描范围（该文件的 `SOURCE_ROOTS`）只有 `server/src`、`packages/shared/src`、`miniprogram`——**admin-web、checkout-static、scripts 不在机器校验内**，这三处的注释规范目前只靠 review（AJ-176 补注：强制范围与文首"适用范围"不等宽）

# 第二部分：日志体系设计

## 5. 目标（出问题时的六个必须回答）

> 谁（user/openid/admin）｜何时（ts）｜哪个请求/订单（`trace_id` / `req_id` / `order_id`）｜做了什么（`event` + 入参摘要）｜结果（status / err）｜耗时（duration_ms）

做不到这六条的日志，视为没记。

## 6. 三条日志流（严格分开，不混用）

| 流 | 用途 | 载体 | 保留 | 采样 |
|---|---|---|---|---|
| **A. 运行日志** | 排查故障：HTTP 进出、外部调用、慢查询、异常 | `pino` JSON → stdout（Render） + Sentry（error 聚合，`beforeSend` 脱敏，D-52）（⚠️ **Sentry 未落地**：只有 `SENTRY_DSN` 配置键，无 SDK、无使用方，AJ-176） | 平台 7–30 天 | 全量（生产 info+） |
| **B. 业务审计日志** | 不可否认定责：状态迁移、支付回调、退款、拒付、改价、上下架、管理员操作 | **DB `order_events`**（事实来源）+ `admin_audit` 表（⚠️ `admin_audit` **表已建、未接线**——全仓无写入方（AJ-150 欠账）。落地前，订单类管理员操作（发货 / 退款 / 退款失败 / 改址）的留痕在 `order_events.actor = admin:<sub>`（一致性审计 C3）；改价 / 上下架 / 改汇率 / 拉黑 / Banner 等非订单操作目前只有运行日志，AJ-176） | 永久 | 100%，禁止采样 |
| **C. 用户行为日志** | 转化分析：浏览/搜索/加购/下单/支付入口点击/复制链接/支付结果 | DB `user_events` 表 + 小程序 RealtimeLogManager（~~⚠️ `user_events` 表已建、未接线~~ **2026-10-08 已接线（AJ-409 / M-21）**：`POST /api/v1/beacon` 是唯一写入方，白名单五事件——page_view / add_to_cart / checkout_enter / pay_start / pay_abandon；搜索、复制链接、支付结果尚未进流 C） | ~~≥12 个月~~ 180 天（AJ-138；AJ-176 更正） | 高频浏览可采样，**下单与支付 100%** |

## 7. 字段约定（统一，不许各自发明）

```jsonc
{
  "ts": "2026-09-22T10:00:00.123Z",   // ISO8601，UTC
  "level": "info",                     // debug|info|warn|error
  "event": "pay_intent_created",       // 事件名（AJ-176 更正原 "msg": "order.pay.create"）：logger 的 messageKey 就是 event、不是 msg；运行日志一律 snake_case，实名见 §9.1
  "trace_id": "01J…",                  // 一次用户操作贯穿：小程序 → API → DB → 回调（回调侧靠 order_id 回填）
  "req_id": "01J…",                    // 单次 HTTP（中间件生成，响应头回传 X-Request-Id）
  "user_id": "u_01J…",                 // 内部用户 ID（不写 openid 明文）
  "actor": "user:u_01J…|admin:a_01J…|system|provider",   // 角色:身份，只写角色无法追责（D22）
  "order_id": "o_01J…", "order_no": "W20260922XXXX",
  "channel": "mock|stripe|wechat",
  "module": "payment",                 // 原示例此处另有 "event": "create_payment"——事件键只有上面一个（AJ-176）
  "duration_ms": 128,
  "client_ip": "203.0.113.9", "resp_bytes": 512,          // 仅访问日志（http_request）携带，D22
  "result": "ok|error|ignored", "code": 0,
  "err": { "type": "StripeApiError", "message": "…", "stack": "…" },   // 仅 error
  "ctx": { "amount_jpy": 12800, "currency": "USD", "attempt": 1 }      // 业务关键入参，禁止放敏感值
}
```

**字段归属规则（v1.3，D8/D9）**：`trace_id` / `req_id` / `user_id` / `actor` / `module` 是**身份与归属**字段，只能来自请求上下文（`patchContext`）或 `logger.child()` 绑定，**调用点不得传**。~~非生产环境传了会直接抛错（早炸），生产环境改名~~ **仅 development / test** 传了会直接抛错（早炸）；**staging 与生产同组**：改名为 `field_<key>` 并记 `reserved_dropped`（一条日志不能让请求失败；staging 刻意与生产同组是为了彩排生产行为，N23，见 `server/src/logger.ts` 的 `strict`；AJ-176 更正）。`module` 是唯一例外：child 绑定优先于上下文——传输层中间件曾把请求内所有模块都记成 `http`，按模块过滤因此失效。

**小程序端**：`utils/request.js`（小程序侧 utils ~~必须是~~ 以 .js 为主，见 `price-format.js` 文件头）统一注入 `X-Trace-Id` ~~+ `X-Request-Id`~~；关键行为上报 `POST /beacon`（批量、~~失败静默重试~~ **失败即丢、不重试**——AJ-409 改口径：重试会让弱网用户恢复时一次冲出大批事件）（✅ AJ-409：`utils/beacon.js`，15 秒 / 攒满 20 条 / 切后台冲刷）；`wx.getRealtimeLogManager()` 打实时日志（线上问题可查，需真机）。
（AJ-176 更正，以代码为准：① utils **以 .js 为主**（组件经 miniprogram-simulate 的 Node `require` 只能加载 .js，理由见 `price-format.js` 文件头），`storage.ts` / `wx-api.ts` 是 .ts；页面逻辑放 `pages/*/index.vm.js`（CLAUDE.md 约束十一）。② `request.js` **只注入 `x-trace-id`**；`X-Request-Id` 由服务端每个请求新生成并在响应头回传（`server/src/http.ts` 请求上下文中间件），客户端不注入。③ **`/beacon` 未实现**——契约与服务端都没有这条路由，`request.js` / `app.js` 注释标"待 F5 补完"；现状只有 RealtimeLogManager 实时日志。）

**小程序端错误收集（v1.2 补）**：Sentry 对小程序支持不佳且非官方 → 小程序侧错误（未捕获异常、`wx.request` 失败、`onError`）走 **RealtimeLogManager + `/beacon` 的 `error` 事件上报落库**，与后端共享同一 `trace_id`，管理端"错误列表"可见。（⚠️ 未落地：现状只有 RealtimeLogManager；`/beacon` 上报、落库与管理端"错误列表"均未实现，AJ-176）

**可检索落点（v1.2 补）**：Render 自带日志保留有限、且不适合按 `trace_id` 检索 → 运行日志输出到**可检索日志服务**（Better Stack / Axiom 等，保留 ≥90 天）；业务审计与用户行为在 Postgres 长期保留。（⚠️ 未落地：运行日志当前只到 stdout，未接任何日志服务，AJ-176）

**APPI 合规（v1.2 补）**：隐私政策必须写明行为数据的**收集目的与保留期**（`user_events` ~~≥12 个月~~ **180 天**，AJ-138；AJ-176 更正），并提供"用户要求删除时按 `user_id` 清除其全部行为记录"的**后台操作路径 + 审计留痕**（该操作本身也要写 `admin_audit`）。（✅ 2026-10-09 落地，AJ-413：`DELETE /admin/customers/{id}/events` 删该用户全部行为记录，reason 必填并由审计中间件写入 `admin_audit`；180 天保留期由 daily 作业 `user_events_retention` 自动清理；两者都走迁移 036 的"事务内 GUC 窄口"，普通 UPDATE / DELETE 仍被触发器拒绝）

## 8. 脱敏红线（写进 lint 与 review）

| 禁止记录 | 允许记录 |
|---|---|
| `APP_SECRET`、JWT 原文、~~`Idempotency-Key` 原文~~（AJ-176 移出，见表后说明）、Stripe `whsec`、密码 | 它们的**校验结果**（ok/fail） |
| 卡号 / CVV / 完整邮箱 / 完整电话 / 完整地址 | 掩码：`a***@gmail.com`、`+1***1234`、只记城市与州 |
| openid 明文 | 内部 `user_id`；~~确需时截断前 8 位~~ 键名命中 `openid` 时保留**尾 4 位**（`maskTail` 先剥非数字再取尾 4 位，实测 `o6_bmjrPTlm6_2sgVt7hMZOPfL2M` → `***6272`），自由文本里的 openid 形态保留**首 2 尾 2**（→ `o6***2M`）（`server/src/redact.ts` 的 `maskIdentifier` / `maskText`；AJ-176 更正） |
| 回调**原始报文**（含签名与个人信息） | 事件类型、`provider_ref`、`transaction_id`、验签结果、处理结论 |

**`Idempotency-Key`：允许进运行日志，但不得与请求体同条输出**（AJ-176 决策，改写原"原文禁止记录"红线）。
日志里的键是服务端拼好作用域后的形态 `用户:路由:客户端键`（`server/src/ports/idempotency.ts` 的 `scopeKey()`；客户端键 ≤128 字符），
客户端键是随机生成的请求标识、不是个人信息，而排查"重复下单 / 重复提交"时它是**唯一**能把两次请求对上的线索。
依据文件：`server/src/redact.ts`（`SENSITIVE_PHRASES` 的 @why：`key` 是通用词、不进敏感单词表，换来"幂等键仍可在日志里查到"——**有意不遮蔽**；
`server/src/redact.unit.test.ts`「idempotency_key 不被打码」钉住该行为）、`server/src/adapters/idempotency.ts`
（`idempotency_lease_lost` / `idempotency_lease_renew_lost` / `idempotency_lease_renew_failed` 只记 `route` + `ctx.key` + 结论，不带请求体）。
仍然禁止的是把键与**请求体**（地址、电话、邮箱等）写在同一条日志里——请求体本就不进日志（《地基搭建清单》附录 C #6：解析错误日志也不再带请求体片段）。

统一走 `redact()` 工具（一处定义、全局调用），Sentry `beforeSend` 复用它（D-52 已要求脱敏，此处补实现口径；⚠️ Sentry 尚未接入，这半句是接入时的口径，AJ-176）。

### 9.1 规范名 → 实际事件名对照（AJ-176；名字 grep 自 `server/src` 非测试文件，2026-09-28）
