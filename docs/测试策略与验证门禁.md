# 测试策略与验证门禁（Test Strategy & Gates）

> 状态：已定 ｜ 版本：v1.0（2026-09-22）｜ 适用范围：`jp_project` 全部代码（server / miniprogram / checkout-static / admin-web）
> 依据：用户 2026-09-22 明确要求——**没有严格测试不得进入下一步**；最小单元开发；假数据必须完整模拟真实场景。
> 上游契约：《技术文档 v0.5》《api-contract.yaml 0.5.0》《工程框架 v0.5》《需求文档 PRD v1.6》
> ⚠️ 本文是**工程侧单一事实来源**，治理文档库（jp）只放链接不放内容。

## 1. 四条铁律（不可协商）

| 编号 | 铁律 | 具体含义 |
|---|---|---|
| **T-1** | **无绿灯不写下一步** | 上一个单元的全部测试（含新增 + 存量回归）未通过，禁止开始新单元。不是"写完再补测试"，是"测试绿了才算这一步完成" |
| **T-2** | **先红后绿** | 每个单元先写失败测试（红灯），确认它真的会失败（能捕获预期错误），再写最小实现让它变绿。先写实现后补的测试不算数 |
| **T-3** | **依赖要真，只有第三方要假** | 数据库用**真实 Postgres**（禁用内存假 DB / SQLite 替代）；HTTP 走**真实路由**（supertest）；只有**外部三方**（Stripe / 微信机构 / R2 / 邮件）用形状与官方一致的录制 Fixture。验签逻辑必须走真实代码路径，不允许 mock 掉验签 |
| **T-4** | **假数据必须像真的** | Fixture 覆盖真实边界与异常形状（见 §5），不是"能跑通就行"。宁可多一个反例，不要少一个分支 |

**违规处理**：任何一步没跑测试就往下写，停下来回退到未验证的那一步，补齐测试后再继续。这条对 AI 助手和人同时生效。

## 2. 最小单元的定义（切分粒度）

| 单元类型 | 例子 | 实现代码上限 | 必带测试 |
|---|---|---|---|
| **纯函数单元** | 运费取档、金额计算、状态机迁移判断、格式化、校验函数 | ≤ 60 行 | L0 单测（含边界表） |
| **存储单元** | 一个表的 repository 方法（含 SQL） | ≤ 80 行 | L1 集成（真库，事务回滚） |
| **接口单元** | 一个路由（成功 + 主要错误码） | ≤ 100 行 | L1 + L2 契约断言 |
| **适配单元** | PaymentProvider 的一个方法（create / verify / refund） | ≤ 100 行 | L0 + L1（含回调重放） |
| **任务单元** | 调度器一个子任务（超时关单 / 自动签收） | ≤ 80 行 | L1（含并发锁与 savepoint） |
| **页面单元** | 小程序一个页面（逻辑 + 结构） | 1 页 | L0（抽出的纯逻辑）+ L4 手工清单 |

**规则**：一次只做**一个**单元；一个单元 = 一个 commit（`test(...)` / `feat(...)` 可拆两个 commit）；单次交付总增量控制在 ~150 行实现 + 对应测试以内。超过就拆分。

## 3. 测试分层

| 层 | 名称 | 范围 | 工具 | 依赖 | 速度 |
|---|---|---|---|---|---|
| **L0** | 单元 | 纯函数、校验、状态机、金额、运费取档 | Vitest | 无 | ms |
| **L1** | 集成 | repository SQL、路由、调度器、回调 | Vitest + supertest + postgres.js | **真 Postgres**（`japan_shop_test`） | 100ms |
| **L2** | 契约 | 每个路径的状态码 / 必填字段 / 错误码枚举 | Vitest + 断言表（由 api-contract 0.5.0 派生） | 真库 + 真路由 | 100ms |
| **L3** | 端到端 | Mock 通道全流程：登录 → 加购 → 报价 → 建单 → 支付 → 回调 → 发货 → 签收 → 完成；含超时关单、退款、拒付 | Vitest（串行） | 真库 + 真路由 | s |
| **L4** | 手工 | 真机/开发者工具：登录、复制链接跳 Stripe、隐私弹窗、页面视觉、上传 | 微信开发者工具 + 浏览器 | 真设备 | 人工 |
| **LM** | 元（meta） | **门禁本身**：断言 ESLint 的类型感知规则真的挂上了、工程配置文件没漂移 | Vitest + ESLint Node API | 无 | s |

**LM 存在的理由**：L0–L4 全绿有两种可能——规则生效且代码干净，或者规则压根没挂上，两者从输出看一模一样。
删除 lint 规则、删掉小程序的 `project.config.json`，都不会让任何一层变红（那些文件不在 L0 的视野里）。
LM 就是给"门禁"自己装的那道门：它 lint 一份**故意违规**的夹具，断言规则确实报了错。

### 3.1 数据库隔离策略（关键）

- 测试库 `japan_shop_test`，**迁移 SQL 与生产同一套**（仓库根 `migrations/*.sql`，001–007），禁止"测试专用 DDL"
- 每个用例：`BEGIN` → 执行 → `ROLLBACK`（用 postgres.js 的事务），用例间零污染、顺序无关
- 需要真并发的用例（幂等键、 advisory lock）单独用 `describe.concurrent` 之外的独立连接，**不共享事务**
- 每个测试文件前用 `resetTestDb()` 重置（`test/db/test-db.ts`：TRUNCATE 全部表，**配置表排除名单**——pgmigrations / job_runs / country_profiles，种子数据不会被清掉），防跨文件污染；迁移与生产同套防迁移漂移，迁移执行走 `npm run db:migrate`

### 3.2 时间与随机

- 时间：`vi.setSystemTime('2026-09-22T00:00:00Z')` 冻结；TTL、自动签收、自动完成全部用假时间推进，禁止 `sleep`
- ID：固定 seed 的 ULID 工厂，禁止真实随机导致断言不稳定
- 调度器：暴露 `runSchedulerOnce()` 供测试直接调用，不依赖 60s 定时器

## 4. 门禁（Gate）

### 4.1 每个单元的 DoD（全部满足才算完成）

- [ ] 新增测试先红后绿（保留红灯证据：首次运行失败输出）
- [ ] `npm run gate` 全绿（L0+L1+L2+L3 串行）
- [ ] 存量测试无跳过（`.skip` / `.todo` 必须有登记的原因与期限）
- [ ] 关键模块分支覆盖率 **100%**（见 §4.2）
- [ ] 错误码与状态机迁移与《技术文档 v0.5》逐条一致（改契约先改文档）
- [ ] L4 手工项已列入 §7 清单并标注状态（不得静默跳过）

### 4.2 覆盖率硬指标

| 模块 | 要求 |
|---|---|
| `shipping`（运费取档） | **分支 100%**（含所有档位边界 ±1g） |
| `orders` 状态机 + 幂等 + 换通道 | **分支 100%** |
| `payment` 适配层（create / verify / refund / 回调重放） | **分支 100%** |
| 金额计算（整数円、fx 快照、退款原币） | **分支 100%** |
| 上架校验（origin_country / 重量 / 合规标签） | **分支 100%** |
| 其余 server 代码 | 行 ≥ 85% |
| miniprogram 抽出的纯逻辑 | 行 ≥ 80%（页面渲染不在内，走 L4） |

### 4.3 全局门禁命令

```bash
npm run test:fast      # 快档：只跑与本次改动相关的测试，时间预算 ≤30s（写每个单元时执行）
npm run lint           # ESLint（类型检查是独立脚本 npm run typecheck：tsc --noEmit，类型零错误）
npm run test:unit      # L0
npm run test:db        # L1 + L2（自动起/重置 japan_shop_test）
npm run test:e2e       # L3
npm run test:lint      # LM：门禁的门禁（断言类型感知规则与工程配置没被悄悄去掉）
npm run cov            # 覆盖率，低于阈值直接非零退出
npm run gate           # 以上串行，任一失败即中断（CI 与本地同一条）
```

**CI（已搭建，A6）**：`.github/workflows/ci.yml` —— push/PR 到 `main` 时跑 `npm run gate`，
Postgres 16 service container，Node 22，`npm ci`，**红即禁止合并**。
只注入 `DATABASE_URL` / `JWT_SECRET` / `TERMS_VERSION` 三个变量（实测足够，见 `docs/自主决策记录.md` AJ-21）。

> ⚠️ **`npm run cov` 在本机会假红（环境限制，不是门禁问题）**
> 覆盖率的**阈值判定发生在清理临时文件之前**（`@vitest/coverage-v8/dist/provider.js:115` 调
> `reportThresholds()`，`cleanAfterRun()` 在之后的 `reportCoverage()` 才调）。
> 本机沙箱会拦掉 `coverage/.tmp` 的批量删除（`count:78 > threshold:50`），于是
> **即便全绿也会 exit 1**。判读办法：日志里**没有** `does not meet global threshold` 就是达标
> （红灯已验：只跑 unit 时覆盖率 68%，会明确报这一行）。GitHub Actions 上没有这道拦截，`cov` 正常 exit 0。
> 详见 `docs/自主决策记录.md` AJ-23。

## 5. Fixture（假数据）规格 —— 必须完整模拟真实场景

目录：`test/factories/`（现行工厂体系：`catalog` / `stripe` / `us-address` / `entities` / `scenarios` / `anti-examples` / `seed-bundle` + `manifest/` 真实形态清单），全部**确定性**（固定 seed、固定时间、固定 ULID）。每类 fixture 必须先写「真实形态清单」再写数据，由 `manifest/` 的双向 `audit()` 守住（见 CLAUDE.md 约束三）。

| Fixture | 内容要求（不是示意，是必须项） |
|---|---|
| `products` | 10 个 SKU：厨刀 / 保温杯 / SK-II / 食品 / 化妆品 + **5 个反例**（防晒 `sunscreen`、医薬部外品 `quasi_drug`、儿童用品、酒类、电器）触发上架拦截；每个含 `price_jpy` 整数円、`weight_g>0`、`origin_country='JP'`、`customs_desc_en`、合规标签位；含 `weight_g=0` 与 `origin_country='CN'` 的非法样本 |
| `shipping_rates` | 分档表含锚点 2kg=4,950；边界样本 `w=249/250/251`、`w=100/101`、`w=500/501`、`w=1850`、`w=2000/2001`、`w=0`、`w` 超最大档 |
| `addresses` | 美国真实格式：`street1/2`、`city`、`state`（2 字母）、`zip5` 与 `zip5+4`、电话；含**非 ASCII 反例**（中文姓名/地址）验证 ASCII 校验 |
| `users` | 已授权买家、管理员（email + bcrypt hash）、`blocked_at` 已拉黑、被限流 |
| `fx_rates` | JPY→CNY / JPY→USD 两条 + 缓冲 3%；含 0 / 极大 / 缺失（应报 50003） |
| `orders` | 覆盖 10 态各一份；件数 N=1/2/4/8；跨档重量组合；`terms_version` 旧版本（40011）；`is_test` 审核单 |
| `stripe.events` | **官方真实事件 JSON 形状**：`checkout.session.completed`、`payment_intent.succeeded`、`charge.dispute.created/closed`；签名用官方 `stripe.webhooks.generateTestHeaderString`（走真实验签，不 mock） |
| `wechat.callback` | 按技术文档 §4 字段构造：成功 / 失败 / **重复投递** / **乱序（迟到）** / 签名错误 / 金额不符 |
| `admin` | 初始管理员 seed（`ADMIN_EMAIL` + bcrypt）、登录失败 5 次锁定（42901） |

**原则**：Fixture 里出现真实世界会出现的每一种"脏"输入——空字符串、非 ASCII、越界数值、重复请求、乱序事件、过期时间。测试通过的代价是这些都被覆盖，而不是只跑 happy path。

## 8. 每次交付的固定动作（AI 助手执行，缺一不可）

1. 声明本单元（类型 + 上限内的改动范围）
2. 先写测试 → 跑一次**确认红灯** → 贴失败输出
3. 写最小实现 → 跑 `npm run gate`
4. 贴：新增/修改文件、测试命令、**测试输出摘要**（通过数/失败数）、覆盖率增量、L4 待办
5. 全绿才算这一步结束；红灯**立即停下修**，不进入下一单元
6. 单单元一个 commit；推送前跑 `git status` 确认无 `.env` 等敏感文件

## 9. 工具链定案

| 用途 | 选型 | 理由 |
|---|---|---|
| 测试框架 | **Vitest** | TS 开箱、假时间、v8 覆盖率、快照、串行/并发控制；比 `node:test` 少一半胶水 |
| HTTP 集成 | **supertest** + 导出 `createApp()` | 打真实路由与中间件，不复制逻辑 |
| 数据库 | **postgres.js** 真库 + 事务回滚 | 铁律 T-3：禁止假 DB |
| 时间 | `vi.setSystemTime` / `vi.useFakeTimers` | 禁止 sleep |
| 契约 | 由 `api-contract.yaml 0.5.0` 派生的断言表（不做完整 OpenAPI 校验，性价比低） | 覆盖状态码 + 必填字段 + 错误码枚举 |
| 覆盖率 | v8 provider，阈值写进 `vitest.config.mts`（低于阈值非零退出）；阈值表的唯一事实来源是 `vitest.coverage-gates.ts` | 门禁硬指标 |
| 小程序逻辑 | 可测逻辑一律抽到 `utils/*.ts`（纯函数），页面只做绑定 | 让 L0 能覆盖；页面渲染走 L4 |
| CI | GitHub Actions 跑 `npm run gate`；本地 pre-commit 跑 `lint + test:unit` | 未搭 CI 前本地等价 |
