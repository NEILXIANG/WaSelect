## 1. 四条铁律（不可协商）

| 编号 | 铁律 | 具体含义 |
|---|---|---|
| **T-1** | **无绿灯不写下一步** | 上一个单元的全部测试（含新增 + 存量回归）未通过，禁止开始新单元。不是"写完再补测试"，是"测试绿了才算这一步完成" |
| **T-2** | **先红后绿** | 每个单元先写失败测试（红灯），确认它真的会失败（能捕获预期错误），再写最小实现让它变绿。先写实现后补的测试不算数 |
| **T-3** | **依赖要真，只有第三方要假** | 数据库用**真实 Postgres**（禁用内存假 DB / SQLite 替代）；HTTP 走**真实路由**（~~supertest~~ `createHttpApp()` + 真 `listen()` 端口，见 `test/e2e/harness.ts`；仓库没有 supertest，AJ-176）；只有**外部三方**（Stripe / 微信机构 / R2 / 邮件）用形状与官方一致的录制 Fixture。验签逻辑必须走真实代码路径，不允许 mock 掉验签 |
| **T-4** | **假数据必须像真的** | Fixture 覆盖真实边界与异常形状（见 §5），不是"能跑通就行"。宁可多一个反例，不要少一个分支 |

**违规处理**：任何一步没跑测试就往下写，停下来回退到未验证的那一步，补齐测试后再继续。这条对 AI 助手和人同时生效。

## 2. 最小单元的定义（切分粒度）

| 单元类型 | 例子 | 实现代码上限 | 必带测试 |
|---|---|---|---|
| **纯函数单元** | 运费取档、金额计算、状态机迁移判断、格式化、校验函数 | ≤ 60 行 | L0 单测（含边界表） |
| **存储单元** | 一个表的 repository 方法（含 SQL） | ≤ 80 行 | L1 集成（真库，事务回滚） |
| **接口单元** | 一个路由（成功 + 主要错误码） | ≤ 100 行 | L1 + L2 契约断言 |
| **适配单元** | PaymentProvider 的一个方法（create / verify / refund） | ≤ 100 行 | L0 + L1（含回调重放） |
| **任务单元** | 调度器一个子任务（超时关单 / 自动签收） | ≤ 80 行 | L1（含并发锁与 savepoint） |
| **页面单元** | 小程序一个页面（逻辑 + 结构） | 1 页 | L0（抽出的纯逻辑）+ L4 手工清单 |

**规则**：一次只做**一个**单元；一个单元 = 一个 commit（`test(...)` / `feat(...)` 可拆两个 commit）；单次交付总增量控制在 ~150 行实现 + 对应测试以内。超过就拆分。

## 3. 测试分层

| 层 | 名称 | 范围 | 工具 | 依赖 | 速度 |
|---|---|---|---|---|---|
| **L0** | 单元 | 纯函数、校验、状态机、金额、运费取档 | Vitest | 无 | ms |
| **L1** | 集成 | repository SQL、路由、调度器、回调 | Vitest + `createHttpApp` + 真 `listen` 端口（~~supertest~~，AJ-176）+ postgres.js | **真 Postgres**（`japan_shop_test`） | 100ms |
| **L2** | 契约 | 每个路径的状态码 / 必填字段 / 错误码枚举 | Vitest `contract` project（`*.contract.test.ts`）+ 断言表（由 `contracts/api-contract.yaml` 派生，版本以其 `info.version` 为准） | ~~真库 + 真路由~~ **不连库**（AJ-176：routes.contract / config.contract / contract-document 等全部无 DB；路由面走 `mountAllRoutes` 快照 + 调用即抛的 stub） | 100ms |
| **L3** | 端到端 | Mock 通道全流程：登录 → 加购 → 报价 → 建单 → 支付 → 回调 → 发货 → 签收 → 完成；含超时关单、退款、拒付（「发货 → 签收 → 完成」由每日作业驱动，L1 覆盖在 `auto-fulfilment.db.test.ts` / `internal-jobs.db.test.ts`（AJ-182）；e2e 仍无这一段） | Vitest（串行） | 真库 + 真路由 | s |
| **L4** | 手工 | 真机/开发者工具：登录、复制链接跳 Stripe、隐私弹窗、页面视觉、上传 | 微信开发者工具 + 浏览器 | 真设备 | 人工 |
| **LM** | 元（meta） | **门禁本身**：断言 ESLint 的类型感知规则真的挂上了、工程配置文件没漂移 | Vitest + ESLint Node API | 无 | s |

**LM 存在的理由**：L0–L4 全绿有两种可能——规则生效且代码干净，或者规则压根没挂上，两者从输出看一模一样。
删除 lint 规则、删掉小程序的 `project.config.json`，都不会让任何一层变红（那些文件不在 L0 的视野里）。
LM 就是给"门禁"自己装的那道门：它 lint 一份**故意违规**的夹具，断言规则确实报了错。

### 3.1 数据库隔离策略（关键）

- 测试库 `japan_shop_test`，**迁移 SQL 与生产同一套**（仓库根 `migrations/*.sql`，当前 001–013 共 20 张表；真源：`server/src/adapters/db.db.test.ts` 的表数断言 + `migrations/`；AJ-176 更正原 ~~001–009~~），禁止"测试专用 DDL"
- 每个用例：`BEGIN` → 执行 → `ROLLBACK`（用 postgres.js 的事务），用例间零污染、顺序无关
- 需要真并发的用例（幂等键、 advisory lock）单独用 `describe.concurrent` 之外的独立连接，**不共享事务**
- 每个测试文件前用 `resetTestDb()` 重置（`test/db/test-db.ts`：TRUNCATE 全部表，**配置表排除名单**——pgmigrations / job_runs / country_profiles / duty_rates / payment_channels / app_config（真源 `test/db/test-db.ts` 的 `not in (…)`；AJ-176 补齐后三张），种子数据不会被清掉），防跨文件污染；迁移与生产同套防迁移漂移，迁移执行走 `npm run db:migrate`

### 3.2 时间与随机

- 时间：~~`vi.setSystemTime('2026-09-22T00:00:00Z')` 冻结~~ 以**注入 `Clock`** 为主（`test/helpers/fixed-clock.ts` 的 `fixedClock` / `mutableClock`；业务代码受 F10 纯度门禁约束、不得直接取时间），`vi.setSystemTime` 全库仅个别文件使用（当前 2 个；AJ-176）；TTL、自动签收、自动完成全部用假时间推进（后两者尚未实现），禁止 `sleep`
- ID：固定 seed 的确定性 ID 工厂（`test/factories` 的 `createIdFactory`，形状像 ULID 但不含时间序；生产 ID 是带前缀的 UUID v4——AJ-176 更正原「ULID 工厂」），禁止真实随机导致断言不稳定
- 调度器：暴露 `runSchedulerOnce()` 供测试直接调用，不依赖 60s 定时器

### 3.3 链路覆盖矩阵（接缝断言——"各件各自绿"不等于"拼起来对"）

> @why 两轮全面审计（AJ-85/87）的 P1 级缺陷有**共同形态**：每个模块自己的测试全绿，
> 但**模块之间的接缝**没人测——e2e harness 手工拼注册表绕过了生产装配函数
> （`buildPaymentRegistry` 改动零链路覆盖）、Stripe 回调从 HTTP 到落账的链路只有单测。
> 覆盖率数字对此完全无感：被绕过的代码行照样被单测覆盖着。
> 所以每条**钱 / 状态 / 配置的链路**必须在这条矩阵里有一行，标明它在哪一层被端到端验证；
> **新件交付时必须回答"它与既有件的接缝断言在哪"**（答"没有"就要么补、要么登记欠账带触发条件）。

> ⚠️ **判定只认退出码，不按日志措辞判读**（AJ-423 订正，2026-10-09）
