## 2. 走过的场景（两端对照）

1. 买家：首页 → 切分类 → 搜无结果 → 清除搜索 → 详情（同类推荐）→ 加购 → 购物车 → 结算（无地址）→ 新增地址（故意填错电话 / 邮编 / 不选州）→ 下单 → 付款
2. 运营：订单列表看到新单 → 详情（地址 / 邮箱 / 金额与买家填的一致）→ 发货（运单号小写带空格，二次确认）→ **买家端**同单变"已发货 · 国际运输中"、运单号一致
3. 买家：低库存刀具选数量（到库存封顶）→ 立即购买（邮箱自动带出）→ 小程序内付款 → 运营部分退款 2,000 円（先故意写"2,000"、不选原因）→ **买家端**出现"部分退款 2,000 円 · 已退回"
4. 买家加购 KINTO → 运营下架 → **买家购物车**标红、结算拦住并说明出路 → 取消勾选后其余照常结算
5. 买家确认收货 → 已送达 → 再次购买（放回购物车）
6. 运营：删除坏图 Banner → **买家首页**轮播恢复；运营日志、客户页、工作台数字与操作逐条对得上

## 4. 只记录、不改（设计取舍或需用户拍板）

| # | 观察 | 为什么没改 |
|---|---|---|
| O1 | 后台保存失败只给通用"参数缺失或格式错误"，字段明细只进日志 | `admin-product-routes.ts` @limitation 一的既有设计（前端解释、后端兜底）；改成回字段名是方针变化 |
| O2 | 买家看不到部分退款的**原因** | 契约 `BuyerPartialRefund` 刻意不含 reason（内部信息） |
| O3 | 订单合计旁没有"已退 X / 实付 Y" | 需要定口径（退款是否含运费等），先记录 |
| O4 | "已送达"时进度条最后一格仍是空心圈 | 测试锁定的既有设计：delivered 之后还有 completed，五格全满留给 completed；视觉上易读成"没到" |
| O5 | 购物车里下架商品取消勾选后标红消失，下次可能又勾回来 | 未勾选的不报价、拿不到状态；要做需单独查一次 |
| O6 | 模拟环境 `REVIEW_MODE=off` 且未开 `MOCK_AUTO_CONFIRM` 时，小程序内模拟支付走不通 | 只影响本地；生产 mock 只在审核期且自动确认 |
| O7 | 订单列表"刷新"之前不会自动更新新单 | 有刷新按钮，属常规行为；如需自动刷新另议 |

## 5. 走查中纠正过的误判

- 新订单起初没出现在后台列表，我一度判断为"审核模式下自动归为测试单"——**错**：sim 环境 `REVIEW_MODE=off`，
  实际是列表页没重新取数（同一网址导航不触发重取），点「刷新」即出现。
- 一次 40401 是我脚本拼错了商品 id（多带了数量），不是商品问题。
- 商品页地址栏参数是 `q` 不是 `keyword`，搜不出来是我写错。
