## 二、§2 新增教训

- **第 49 条：扫描型断言最容易写成「自证」**（与第 21 条同源，但更具体）。
  可达性断言第一版只扫"页面 js 里出现过 `'/pages/x/index'` 字面量"，
  而**路径常量声明本身就是那个字面量** → 注入"删掉 `onGoMine`、只留
  `const USER_PAGE = '/pages/user/index'`"时 **exit=0**。
  修法：只从**调用点**（`navigateTo` / `redirectTo` 的 `url:`）取证 + 解析常量表。
  **判定标准**：注入"把用法删掉、只留声明"必须红 —— 这是所有"扫源码"的断言都该做的自检。
- **第 50 条：「能走通」不等于「走得到」**。
  页面注册了、三件套齐备、单测全绿 ≠ 用户能到。订单 / 地址 / 法务三页在 U-H2 之前
  正是这个状态（"主链路已闭环"只成立于人工顺着 `navigateTo` 一路点下去）。
  新增页面时"有没有登记 / 有没有入口"两件事**都不报错**。
  现由 `project-config.unit.test.ts` 两条断言守：登记反向断言 + 可达性断言；
  白名单（名单式，不是"看起来没人链就放过"）：`pages[0]` 启动页、`pages/index/index`、`pages/comp/index`。
- **第 51 条：`git checkout -- <file>` 对新文件无效**（未跟踪文件不在 HEAD 里，
  命令失败但**静默留下注入的改动**，本次差点丢两处）。
  缺陷注入的还原一律用**事先 `cp` 的备份**，不要用 `git checkout`。
- **第 52 条：`date -j -f` 会把输入当本地时区解析（恒等映射陷阱）**。
  BSD `TZ=Asia/Tokyo date -j -f "…" "$t"` 输出 = 输入，第一版 JST 期望值"交叉验证"
  实际什么都没验到。正确做法：`TZ=UTC date -j -f … +%s` 得 epoch →
  `TZ=Asia/Tokyo date -r <epoch>` 换算；另加 Python `datetime + timedelta(hours=9)`
  第三路，8 组全一致才算。已落档：`自主决策记录.md` §2 表第 9 行 + `jst-text.unit.test.ts` 注释。
